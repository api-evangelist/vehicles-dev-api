# Vehicles.dev

Automotive vehicle data platform offering a live REST API for VIN decoding, specifications, recalls, market valuation, depreciation, ownership costs, listings, price history, and photos, backed by federal sources (NHTSA vPIC, NHTSA recalls, EPA) and a continuously crawled US dealer-listings store. Ships an OpenAPI 3.1 contract and a local MCP server exposing all ten endpoints as read-only tools.

- **Provider:** https://vehicles.dev/
- **Documentation:** https://vehicles.dev/docs
- **Base URL:** https://api.vehicles.dev

## APIs

- **Vehicles.dev REST API** — Live, billable REST API with ten GET endpoints under /v1/vehicles/ for VIN decode, specifications, recalls, market value, depreciation, ownership costs, composite report, listings search, listing price history, and photos. Bearer API key auth (vdev_ prefix), server-to-server only, RFC 9457 problem documents. (`https://api.vehicles.dev`)

> Confirmed publicly reachable: REST API at https://api.vehicles.dev and an unauthenticated OpenAPI 3.1 spec at https://api.vehicles.dev/openapi.json. The MCP server (vehicles-dev-mcp on npm, run via npx) is local/stdio only — NOT a hosted remote endpoint — so it is not cataloged as an MCPServer property and does not make the provider agent-native. Docs explicitly state no hosted remote MCP endpoint exists yet. No llms.txt (fetch of https://vehicles.dev/llms.txt could not be confirmed), no agent skills, no GraphQL, no AsyncAPI, no official Postman collection (OpenAPI import is the documented path). Homepage 'preview' language is stale; docs are the authoritative surface describing a live, billable API.
